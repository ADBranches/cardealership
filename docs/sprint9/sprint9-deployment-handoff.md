# Sprint 9 Deployment Handoff

## Deployment scope

This handoff covers the exchange-rate API, scheduled refresh worker, secured bulk vehicle-image endpoint, MongoDB persistence, and development filesystem storage.

## Required environment names

### Runtime

- `PORT`
- `MONGO_URI`
- `JWT_SECRET`

### Exchange rates

- `EXCHANGE_RATE_PROVIDER`
- `EXCHANGE_RATE_BASE_CURRENCY`
- `EXCHANGE_RATE_SUPPORTED_CURRENCIES`
- `EXCHANGE_RATE_REFRESH_INTERVAL_MS`
- `EXCHANGE_RATE_REQUEST_TIMEOUT_MS`
- `EXCHANGE_RATE_CACHE_TTL_MS`
- `EXCHANGE_RATE_MOCK_SCENARIO`

### Bulk image uploads

- `BULK_IMAGE_UPLOAD_FIELD_NAME`
- `BULK_IMAGE_UPLOAD_MAX_FILES`
- `BULK_IMAGE_UPLOAD_MAX_FILE_SIZE_BYTES`
- `BULK_IMAGE_UPLOAD_ALLOWED_MIME_TYPES`
- `BULK_IMAGE_UPLOAD_ALLOWED_EXTENSIONS`

No environment values are recorded in this document.

## Pre-deployment checks

1. Supply deployment secrets through the approved secret manager.
2. Verify MongoDB connectivity and required model indexes.
3. Confirm the administrator provisioning process.
4. Run `npm ci` within the backend directory.
5. Run `npm run test:sprint9`.
6. Confirm the worker starts once and stops cleanly on SIGINT and SIGTERM.
7. Confirm `/api/exchange-rates` returns the expected provider or fallback state.
8. Confirm the bulk endpoint rejects unauthenticated and non-administrator requests.

## Production replacement actions

- Replace the mock exchange-rate provider through the `fetchRates(baseCurrency)` interface.
- Replace local image storage through the `store(file)` and `remove(storageKey)` interface.
- Preserve the service, controller, route, and frontend contracts.
- Add provider and storage operational metrics before production traffic.

## Post-deployment checks

- Verify the health endpoint.
- Verify fresh and fallback exchange-rate responses.
- Upload a permitted test image using a non-production vehicle record.
- Verify image metadata and storage cleanup behavior.
- Verify logs contain no tokens, secrets, file buffers, or database credentials.

## Current limitations

- FX values are generated by a mock provider.
- Image objects are stored on the local filesystem.
- Malware scanning, content-signature inspection, optimization, and CDN delivery are not implemented.
